## Chapter 1 Highlights

# Focus on the Problem
>_"Designers need to focus their attention on the cases where things go wrong, not just on when things work as planned. Actually, this is where the most satisfaction can arise:_
>_when something goes wrong but the machine highlights the problems, then the person understands the issue, takes the proper actions, and the problem is solved." - Ch.1, pg.9_

![Checkout Area](https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcQVYlaSekCDiVDoqtn0UYRNQp1HHJ7Bm3lxW96eHYh1pNF1Zw_Z4n25TQE&s=10)

This clause immediately made me think of grocery stores and the their self-checkout systems. It is common to use one of these systems everyday, and every so often be met with the annoying message, "Unexpected Item in Bagging Area." While the error implies what is wrong-an item is causing an issue-the exact reason for the error is never communicated. Moreover, no solution is ever prompted to users. Just as the passage explains, the lack of a solution to the presented problem creates the apparent confusion and disatisfaction! Thus, while it can be minimal, the design of self-checkouts and this error in particular can cause confusion, frustration, and a lack of satisfaction with using the machine. Users do not know how exactly to solve the issue presented, and if their first or second thought of solving the error doesn't work, can completely halt the flow of use. A similar system that displays not only what is wrong (ideally less vague) but how to solve the error encountered matches what this passage is communicating. For example, in this situation, an error message that tells users to take the last scanned item and replace it on the scale/bagging area would be a more satisfactory design.

# Affordance & Singnifiers
>_"An affordance is a relationship between the properties of an object and the capabilities of the agent that determine just how the object could possibly be used.
>[...] If an affordance or anti-affordance cannot be perceived some means of signaling its presence is required [...]" Ch.1, pg.11-12_

![jean small pocket](https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcTQog17Cx5QkFoP9zbgPw008HqZqwQQS4GkJnEZw_UjjiZLeUUkdUizbgpD&s=10)

Affordance and signals is a very important principle when talking about design. An object or system is only as good as the user knows how to use  it. If there is no indication of what an object might be capable of, or documentation of what a system offers and how to properly use it, it can render objects, functions, and sometimes entire products useless. For myself, I instantly thought of the small pocket in jeans. To this day, no one really knows what it is used for! You _can_ put pocket change in there, but there are much better alternatives that most people carry around everyday (usually inside their bigger pockets!). As far as design goes, there is no strong perceivable signifier as to what this pocket affords a user. Naturally, most do not use this small pocket at all. This tiny pocket is rendered useless in most people's lives, all because there is no easy-to-see signal of what it should be used for.
